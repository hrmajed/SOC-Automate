# INC-2026-0033: AWS access keys stored in plaintext on JMP-ADM-01

## Finding
During a purple-team exercise the red team read `C:\Users\mchen\.aws\credentials` on JMP-ADM-01 and used the
long-lived key for IAM user `m.chen-admin` from outside the corporate NAT (203.0.113.10). The key has
AdministratorAccess and can assume `DataScienceReadRole`, which reads the clinical-trial PHI buckets.

## Detection gaps
- No alert fired when the key was used from a non-corporate IP.
- AssumeRole into DataScienceReadRole from outside the NAT was not monitored.

## Remediation plan
| Action | Owner | Status |
|---|---|---|
| Move cloud admins to IAM Identity Center short-lived credentials | Cloud Platform | **OPEN** |
| SCP condition restricting m.chen-admin to aws:SourceIp 203.0.113.10 | Cloud Security | **OPEN** |
| Alert on API calls by IAM users from non-NAT IPs | SOC | Done (CT-S3-EGRESS-ANOMALY covers S3 only) |

## Response guidance if the key is abused
Deactivate ALL access keys of m.chen-admin (including any newly created ones), revoke active role sessions for
DataScienceReadRole, and review CloudTrail for CreateAccessKey / CreateUser persistence.
